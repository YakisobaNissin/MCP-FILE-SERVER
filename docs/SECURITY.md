# Security notes — M3

- Shared Windows-aware path validation rejects absolute/parent-relative/ambiguous paths. Every existing component is checked with lstat/realpath; protected canonical aliases, links and junctions are rejected. Source/workspace overlap is rejected at startup.
- Dot entries, credential/key names, and database/key exports are protected. Text operations reject binary/non-UTF-8, oversized, non-regular and multiply hard-linked files. The policy is not a secret scanner: keep credentials outside the workspace.
- Reads use bounded descriptors and identity/version rechecks. Creates stage and sync a private temporary file, then publish with an exclusive hard link. Replacements stage and sync, recheck the hash/version, then rename. No overwrite option is exposed.
- A shared in-process queue serializes server mutations. Replacement/deletion require a current expected SHA-256. Deletion also requires literal confirm:true and moves only one text file into `.mcp-trash/<recovery_id>/file`, with original path/hash in `metadata.json`. MCP tools cannot access recovery storage. An operator may restore it manually to a validated unoccupied path; no restore or purge tool exists.
- Audits record known tool/time/outcome/duration/count or safe error code, never arguments, paths or contents. Schema rejections are audited; unidentifiable malformed protocol requests are transport errors.
- Endpoint stays on 127.0.0.1 with explicit Host/Origin guards and required bearer authentication before JSON parsing. Missing/wrong/duplicate credentials return 401. Requests are capped at 256 KiB; tool inputs/outputs retain tighter limits. Tokens are loaded from an external private file and compared by constant-time hashes; no query-string credentials are accepted. This is a single-operator shared token, not OAuth or per-user permissions. Rate limiting and OS sandboxing are not implemented. HTTPS/ngrok setup and residual PM2 advisories: [DEPLOYMENT.md](DEPLOYMENT.md).
- Ordinary Node pathname operations cannot eliminate local link-swap/rename races or make hash checks atomic with replacement. Use a trusted local workspace, one server process, and OS permissions excluding untrusted writers. Other processes are outside the mutation queue; network filesystems and unusual reparse points are unsupported.
- Creation requires a filesystem supporting hard links (tested on this Windows workspace). Staged replacement preserves UTF-8 bytes/BOM/line endings and POSIX mode bits, but does not promise Windows ACL, extended attribute or inode preservation. Crashes may leave hidden staging/recovery files; there is no retention policy or power-loss durability guarantee. Recovery contents and audits still require OS protection.
